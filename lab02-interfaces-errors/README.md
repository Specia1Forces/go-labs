# Лабораторная №2. Интерфейсы и ошибки

## Задача

Лабораторная реализует простой сервис регистрации пользователей. Сервис проверяет входные данные и работает не с конкретным хранилищем, а с интерфейсом `UserRepository`. Реализация `MemoryUserRepository` сохраняет пользователей в обычной `map`.

Цель работы — разобраться с интерфейсами Go, явным возвратом ошибок, ранним завершением функции и сохранением причины ошибки через `%w`.

## Запуск

Из корня репозитория:

```bash
go run ./lab02-interfaces-errors
go test ./lab02-interfaces-errors
```

Из каталога лабораторной:

```bash
go run .
go test .
```

## Как устроена программа

```text
main → UserService → UserRepository → MemoryUserRepository → map[int]User
```

- `main` создаёт зависимости и демонстрирует успешные и ошибочные сценарии.
- `UserService` проверяет данные и вызывает репозиторий.
- `UserRepository` описывает два необходимых метода хранилища.
- `MemoryUserRepository` неявно реализует интерфейс и хранит пользователей в памяти.

## Сравнение с Java

### Интерфейс

Java-класс явно объявляет `implements UserRepository`. В Go такого ключевого слова нет. Тип реализует интерфейс автоматически, если у него есть все необходимые методы с подходящими сигнатурами.

```go
type UserRepository interface {
    Save(user User) error
    FindByID(id int) (User, error)
}
```

`MemoryUserRepository` имеет оба метода, поэтому его указатель можно передать в `NewUserService` как `UserRepository`.

### Ошибки

В Java ошибка обычно передаётся через `throw`, а обработка выполняется через `try/catch`. В Go `error` является обычным возвращаемым значением:

```go
user, err := service.GetUser(1)
if err != nil {
    // обработать ошибку
}
```

Такой подход делает ошибочный путь видимым непосредственно в сигнатуре функции и в месте вызова.

### errors.Is

`errors.Is(err, ErrUserNotFound)` проверяет не только саму ошибку, но и ошибки, обёрнутые внутри неё. Это похоже на поиск причины исключения в Java, но выполняется явно.

### Оборачивание через %w

```go
return fmt.Errorf("get user: %w", err)
```

Функция добавляет контекст, но сохраняет исходную ошибку. Благодаря `%w` вызывающий код всё ещё может обнаружить `ErrUserNotFound` через `errors.Is`.

### Внедрение зависимости

`UserService` получает репозиторий через конструктор. Это похоже на constructor injection в Java, однако здесь не используется DI-контейнер: зависимость создаётся и передаётся вручную в `main`.

## Как ошибка проходит через программу

При поиске отсутствующего пользователя происходят следующие действия:

1. `main` вызывает `service.GetUser(99)`.
2. `UserService` вызывает `repository.FindByID(99)`.
3. Репозиторий не находит ключ в `map` и оборачивает `ErrUserNotFound`.
4. Сервис добавляет контекст `get user`, ещё раз используя `%w`.
5. `main` получает ошибку и распознаёт её через `errors.Is`.

## Почему нет try/catch

Go использует явный возврат ошибок. Функция сообщает о возможной неудаче через тип `error`, а вызывающий код сразу решает, что с ней делать: вернуть выше, обработать или преобразовать. `panic` предназначен не для обычных ошибок пользователя, а для ситуаций, в которых нормальное продолжение программы невозможно.

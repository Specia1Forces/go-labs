# Лабораторная №4. HTTP-сервер на net/http

## Задача

Лабораторная реализует небольшой HTTP API для создания и получения задач. Данные хранятся в памяти, поэтому после остановки программы они исчезают.

Доступны два запроса:

| Метод | Путь | Результат |
|---|---|---|
| `GET` | `/tasks` | JSON-массив всех задач |
| `POST` | `/tasks` | Создание задачи из переданного JSON |

Цель работы — увидеть, как HTTP-сервер, маршрутизация, JSON и обработчики устроены в стандартной библиотеке Go без Spring, Echo или Gin.

## Запуск

Из корня репозитория:

```bash
go run ./lab04-http-server
```

Сервер будет доступен по адресу `http://localhost:8080/tasks`.

Тесты:

```bash
go test ./lab04-http-server
go test -race ./lab04-http-server
```

## Примеры curl

Получение списка задач:

```bash
curl http://localhost:8080/tasks
```

Создание задачи:

```bash
curl -i -X POST http://localhost:8080/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Изучить net/http"}'
```

Запрос с пустым названием:

```bash
curl -i -X POST http://localhost:8080/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":""}'
```

## Путь POST-запроса

1. Клиент отправляет `POST /tasks` с JSON в теле запроса.
2. `http.ListenAndServe` принимает соединение и передаёт запрос в `ServeMux`.
3. `ServeMux` находит обработчик, зарегистрированный для `/tasks`.
4. `handleTasks` проверяет HTTP-метод через `switch`.
5. `createTask` декодирует JSON с помощью `json.Decoder`.
6. Обработчик проверяет, что `title` не пустой.
7. `TaskStore.Add` блокирует хранилище через `Mutex`, создаёт ID и записывает задачу в `map`.
8. `writeJSON` устанавливает `Content-Type`, статус 201 и кодирует задачу в JSON.
9. `net/http` отправляет сформированный ответ клиенту.

## Зачем map защищена Mutex

HTTP-сервер обрабатывает разные запросы конкурентно. Несколько goroutines могут одновременно вызвать `Add` или `List`. Обычная `map` в Go не предназначена для одновременного чтения и записи.

- `Lock` используется при добавлении задачи, потому что изменяются `map` и `nextID`.
- `RLock` используется при чтении списка: несколько читателей могут работать одновременно, пока никто не выполняет запись.
- `defer Unlock` и `defer RUnlock` гарантируют освобождение блокировки перед выходом из метода.

Без блокировки возможны data race, потерянные изменения или аварийное завершение программы.

## Сравнение с Java и Spring

| Go | Java/Spring | Назначение |
|---|---|---|
| HTTP handler | Метод `@RestController` | Обрабатывает конкретный HTTP-запрос |
| `http.ServeMux` | Маршрутизация Spring MVC | Выбирает обработчик по пути запроса |
| `http.ResponseWriter` | `HttpServletResponse` | Формирует заголовки, статус и тело ответа |
| `*http.Request` | `HttpServletRequest` | Содержит метод, путь, заголовки и тело запроса |
| `encoding/json` | Jackson `ObjectMapper` | Преобразует JSON в структуры и обратно |
| `httptest` | MockMvc | Проверяет обработчики без запуска настоящего порта |
| `sync.RWMutex` | `ReentrantReadWriteLock` | Защищает общее состояние при конкурентном доступе |

В Spring маршрутизация и преобразование JSON часто задаются аннотациями. В этой лабораторной каждый шаг виден явно: регистрация пути, проверка метода, декодирование JSON и запись ответа.

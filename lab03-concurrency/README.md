# Лабораторная №3. Конкурентность в Go

## Задача

Лабораторная содержит два независимых примера:

1. Параллельное суммирование слайса с использованием двух goroutines и channel.
2. Потокобезопасный счётчик с использованием `sync.WaitGroup` и `sync.Mutex`.

Цель работы — познакомиться с основными средствами конкурентности Go без сложных паттернов, worker pool и `context`.

## Запуск

Из корня репозитория:

```bash
go run ./lab03-concurrency
go test ./lab03-concurrency
go test -race ./lab03-concurrency
```

Из каталога лабораторной:

```bash
go run .
go test .
go test -race .
```

## Пример 1. ParallelSum

Функция выполняется по шагам:

1. Слайс делится на две части.
2. Создаётся buffered channel, в котором помещаются два значения `int`.
3. Для каждой половины запускается отдельная goroutine.
4. Каждая goroutine считает свою сумму и отправляет результат в channel.
5. `ParallelSum` дважды читает из channel.
6. Если результат ещё не отправлен, чтение ждёт его появления.
7. Две частичные суммы складываются и возвращаются вызывающему коду.

Ключевое слово `go` перед вызовом функции запускает её конкурентно в отдельной goroutine:

```go
go sumPart(numbers[:middle], resultChannel)
```

Канал объявлен как `chan<- int` в `sumPart`. Стрелка показывает, что функция может только отправлять в него значения. Закрывать канал здесь не требуется: программа заранее знает, что будет ровно две отправки и два чтения.

## Пример 2. SafeCounter

Счётчик выполняется по шагам:

1. Создаётся один общий `SafeCounter`.
2. В `WaitGroup` заранее записывается количество запускаемых goroutines — пять.
3. Каждая goroutine вызывает `Increment` 1000 раз.
4. `Lock` разрешает только одной goroutine изменять `value` в конкретный момент.
5. `defer Unlock` освобождает блокировку перед выходом из метода.
6. После завершения работы goroutine вызывает `Done`.
7. `Wait` блокирует продолжение `RunCounter`, пока не завершатся все пять goroutines.
8. Функция возвращает итоговое значение 5000.

## Почему без Mutex возникает data race

Операция `counter.value++` состоит из чтения текущего значения, увеличения и записи результата. Если несколько goroutines выполнят эти действия одновременно, они могут прочитать одно и то же старое значение и перезаписать результаты друг друга.

`sync.Mutex` делает этот участок взаимно исключающим. Пока одна goroutine выполняет увеличение, остальные ждут `Unlock`.

Race detector ищет случаи, когда несколько goroutines одновременно обращаются к одной области памяти и хотя бы одна из них выполняет запись:

```bash
go test -race ./lab03-concurrency
```

## Сравнение с Java

| Go | Приблизительный аналог в Java | Отличие |
|---|---|---|
| goroutine | `Thread` или задача в `ExecutorService` | Goroutine легче системного потока и управляется Go runtime |
| channel | `BlockingQueue` | Channel встроен в язык и используется через операторы `<-` |
| `sync.WaitGroup` | `CountDownLatch` | `Add` задаёт число работ, `Done` уменьшает счётчик, `Wait` ожидает нуля |
| `sync.Mutex` | `synchronized` или `Lock` | Блокировка вызывается явно через `Lock` и `Unlock` |
| race detector | Инструменты обнаружения гонок | Включается стандартной командой `go test -race` |
